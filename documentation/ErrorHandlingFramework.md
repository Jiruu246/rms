# Error Handling Framework

This package gives every layer one shared vocabulary for "what kind of
failure is this" and one shared place to turn that into an HTTP response.

## Responsibility split

```
Database (ent)
    |
Repository   -> converts ent.IsNotFound / ent.IsConstraintError into an
                internal/apperr sentinel; everything else is wrapped with %w
                and left as an opaque internal error
    |
Service      -> passes repo errors through when they're already the right
                sentinel; wraps input/business-rule failures in
                apperr.Invalid / apperr.Conflict / apperr.Unauthorized
    |
Handler      -> one line: apperr.WriteHTTPError(c.Writer, err, fallback)
    |
HTTP response
```

Concretely:

- **Repositories** (`internal/repos/*.go`) are the only place that imports
  `internal/ent` error helpers (`ent.IsNotFound`, `ent.IsConstraintError`).
  Nothing above the repo layer should ever inspect an ent/sql error.
- **Services** (`internal/services/*.go`) return repo errors unchanged when
  no translation is needed (most `GetByID`/`Update`/`Delete` passthroughs),
  and construct `apperr.Invalid`/`apperr.Conflict`/`apperr.Unauthorized` for
  errors that only the service layer can detect (e.g. `order_service.go`'s
  `validateOrderItems`, or `auth_service.go` collapsing "user not found" and
  "wrong password" into one `apperr.Unauthorized("invalid email or
  password")` so login doesn't leak which part was wrong).
- **Handlers** (`internal/handler/*.go`) never branch on error content
  themselves — every error path is `apperr.WriteHTTPError(c.Writer, err,
  "some fallback message")`. This replaced handler-local helpers like
  `restaurant_handler.go`'s old `writeAuthzError` and
  `category_handler.go`'s per-call `errors.Is` chains against pagination
  sentinels.

| File | Contents | Purpose |
|------|----------|---------|
| `errors.go` | `ErrNotFound`, `ErrConflict`, `ErrInvalid`, `ErrUnauthorized`, `ErrForbidden` + constructors `NotFound(format, args...)`, `Invalid(...)`, `Conflict(...)`, `Unauthorized(...)` | Sentinels a caller can `errors.Is` against, plus formatted constructors that `%w`-wrap the sentinel with a caller-supplied, **client-safe** message. Never pass a raw ent/sql error into these — the message is echoed to the API caller as-is. |
| `http.go` | `WriteHTTPError(w, err, fallback)` | The single error -> HTTP status mapping. Checks only this package's five sentinels — every producer (repos, services, `internal/authz`, `pkg/pagination`) reports through them, so there is nothing else to special-case. Anything that doesn't match logs the real error server-side (`log.Printf`) and returns `fallback` to the client — the "Do NOT Expose Database Errors" rule below. |

### Status mapping

| Sentinel | HTTP | Notes |
|----------|------|-------|
| `apperr.ErrNotFound` | 404 | Message is whatever `apperr.NotFound(...)` was called with — always client-authored, never a raw ent error. |
| `apperr.ErrForbidden` | **404** | Returned by `authz.PolicyAuthorizer.Authorize` on a denied decision. Deliberately rendered as 404, not 403: this API never confirms a resource exists to a caller who isn't allowed to see it. Message is a generic `"not found"`, not `err.Error()`. The sentinel is still distinct internally — `errors.Is(err, apperr.ErrForbidden)` works anywhere upstream that wants to log/audit the real reason — only the HTTP layer collapses it into not-found. |
| `apperr.ErrInvalid` | 400 | Bad input — malformed request, failed business validation (e.g. order references an unavailable item), or a `pkg/pagination` parse/validation failure (invalid sort field, cursor/sort mismatch, malformed cursor). |
| `apperr.ErrConflict` | 409 | State conflict — e.g. a unique constraint violation (`ent.IsConstraintError`), like registering a duplicate email. |
| `apperr.ErrUnauthorized` | 401 | A failed authentication attempt with a caller-crafted, safe message (e.g. `"invalid email or password"`). |
| anything else | 500 | Logged via `log.Printf("unexpected error: %v", err)`; client only sees `fallback`. |

## Do NOT Expose Database Errors

Never let an ent/sql error's `.Error()` reach `apperr.WriteHTTPError`'s
non-default branches. The constructors (`apperr.NotFound`, `.Invalid`,
`.Conflict`, `.Unauthorized`) exist precisely so every message that *does*
reach the client was written by the repo/service author, not generated by
the driver. If a repo method can't cleanly classify an error (e.g. an
`ent.IsConstraintError` case it doesn't handle yet), leave it as a plain
`fmt.Errorf("...: %w", err)` — it will correctly fall into
`WriteHTTPError`'s default 500 branch instead of leaking through some other
path.

## Decisions deferred

- **`refresh_token_repo.go`** was intentionally left unconverted: its only
  caller (`auth_service.go`) already discards the specific repo error and
  always returns a generic `apperr.Unauthorized(...)` for security reasons
  (don't reveal whether a refresh token was missing, expired, or revoked),
  so there is no caller today that would benefit from a sentinel there. If a
  future caller needs to distinguish these cases, convert it then.
- **`ent.IsConstraintError` coverage is not exhaustive.** It was added where
  a duplicate-key scenario was easy to reason about (`user_repo.go`'s
  `Create`/`Update` for email uniqueness). Other `Create`/`Update` methods
  still fall through to a generic 500 on a constraint violation — convert
  them the same way if a real duplicate-key endpoint turns out to need a
  409 instead.
